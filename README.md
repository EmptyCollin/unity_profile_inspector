# UPI — Unity 性能自动监测与优化 Agent

一个住在你 Unity 项目里的"体检医生"：定期自动测性能、找问题、开处方，
但**改代码之前一定等你签字**；改完用数据证明"确实好了、没弄坏别的"，
证明不了就自动恢复原样。

## 它怎么工作

```
 定时巡检          发现问题           起草方案            等你批准          落地验证
┌──────────┐   ┌──────────┐   ┌──────────────┐   ┌──────────┐   ┌──────────────┐
│ 打开工程  │ → │ 对比历史  │ → │ 工单五件套：  │ → │ 逐页读完  │ → │ 改代码→编译→  │
│ 采性能数  │   │ 基线与及  │   │ 证据/方案/预 │   │ 抄校验码  │   │ 复测→全指标对 │
│ 据        │   │ 格线      │   │ 期/回滚/预案 │   │ 签字批准  │   │ 比→保留或回滚 │
└──────────┘   └──────────┘   └──────────────┘   └──────────┘   └──────────────┘
```

几个关键设计：
- **每个数字都来自实测采样**，模型只负责解释证据，禁止编造数据；
- **修复前先拍 git 快照**，验证不过一键回到改前；
- **危险改动（影响画面/手感的）永远先报后批**，不给自动执行的机会；
- **改善必须超过噪声带才算数**（3 倍 σ），"感觉变快了"不算；
- 一切留痕：检出率与误报率成对报告，测不到的东西在报告里单列清单。

## 快速开始（Windows）

前置：Python 3.14、Unity 6000.6.7f1（图形界面模式）、`unity` CLI、一个模型密钥。
详细清单见[使用说明](docs/使用说明.md)第二节。

```powershell
# 1. 设密钥（一次性，需要你本人操作）
[Environment]::SetEnvironmentVariable("UNITY_PROFILE_INSPECTOR", "<你的密钥>", "User")

# 2. 自检 → 启动 → 打开界面
python -m upi status     # 全绿再继续
python -m upi start      # 后台启动巡检机器人
python -m upi ui         # 控制台界面：之后所有操作都是按键
```

界面上最常用的键：`r` 立即巡检一轮、`d` 批准/驳回工单、`k` 改配置、
`n` 注册你自己的工程、`l` 标定、`f` 定及格线、`q` 退出界面（机器人不停）、
`Q` 停机。

**接入你自己的工程**：`n` 注册（当场探测回放准入定档 full/partial/none，决定偶发卡顿类问题能否自动修，见 [docs/回放准入标准.md](docs/回放准入标准.md)）→ `l` 标定（约十几分钟）→ `f` 配下限表 → 开盯。

## 能力边界（务必连这段一起了解）

- 数据来自 **PC 编辑器采样**，不等于中低端真机表现；
- 任何 Unity 工程都能**体检**，但**自动修复**只覆盖已建模板的问题类型，
  陌生机制检出后一律转人工；
- 显卡尖峰能发现、不能自动逐笔归因；"量大了以后会炸"类潜在风险暂测不到；
- 完整盲区清单（含解锁路径）见[使用说明第五节](docs/使用说明.md)，
  每份运行报告里也会强制附带。

## 目录结构

```
upi/          管线代码（机器人主体、界面、检测/归因/修复/验证各节点）
probe/        注入编辑器做采样的代码片段（经 unity CLI，非自建插件）
fixtures/     内置演示工程（含故意植入的性能缺陷）
scripts/      测试套件与校验脚本（日常回归 20 套、实测合计 750+ 项检查）
knowledge/    特征库（症状→根因→动作→实测效果，成功失败样本同等入库）
dashboard/    历史统计网页报告
docs/         使用说明、设计文档、认知债清单
runs/         运行留痕（本地独立 git 仓库管理，不进 GitHub，见下）
AGENTS.md     角色契约与硬门禁规则（本项目对 AI 协作者的约束）
DESIGN.md     详细设计
llm_config.yaml  模型服务配置（只存环境变量名，不存密钥值）
```

**关于 `runs/`**：运行留痕全部不进 GitHub（含本机路径与可重采的大体积原始
数据），但本地照旧用 git 管——`runs/` 内挂了一个无远端的独立仓库，工单与
决定的逐版本历史在里面可查。换机器时把 `runs/` 整目录拷走即可。
