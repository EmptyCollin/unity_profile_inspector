# Chroma Rogue 效果设计（v0.1）

> 目标：把 devsim 从“能跑的工程原型”打磨成**看起来像真实小体量商业原型**的游戏；
> 然后在这份基线上，用“日常开发图省事/忘配置”的方式做劣化 case。
> 不追求重度美术，追求：清楚、有手感、轻量、每个反馈都能看见。

---

## 1. 主界面（严格收敛）

主界面**只保留**：

```text
┌────────────────────────────────────────────┐
│  CHROMA ROGUE                              │
│                                            │
│  [ 开始游戏 ]                              │
│  [ 说明 ]                                  │
│                                            │
│  专项测试  [ c18 · 混合            ▾ ]      │
│                                            │
│  本机最高分：12,400 · R8                   │
└────────────────────────────────────────────┘
```

- **开始游戏**：正常基线，所有 `legacy_*` 关闭；
- **说明**：打开规则/道具/BONUS/高级色块说明，不离开主界面；
- **专项测试**：下拉选择 case，选中即加载该 case 的 scenario，等价于：

```text
python sim/replay/devsim_replay.py --case c18
```

- case 列表只显示编号 + 领域短名，不展示 oracle、期望机会、答案；
- UI 与 replay 调用同一个 `CaseRouter`，不允许“自动化能进、界面进不去”；
- 主界面不再放商店/背包/战斗按钮；这些只存在于游戏内流程。

## 2. 视觉方向

### 2.1 风格

**软糖霓虹 / 玻璃糖果**：

- 深海军蓝背景，低对比网格；
- 高饱和色块 + 顶部高光 + 底部投影，做出 2.5D 立体感；
- 不靠大贴图，靠圆角、渐变、描边、阴影、粒子；
- UI 轻、干净，避免“编辑器默认控件”感。

### 2.2 色彩 token

| 用途 | 色值 |
|---|---|
| 背景 | `#070B12` |
| 面板 | `#0E1622` |
| 主文字 | `#E8F1FB` |
| 次文字 | `#91A6BD` |
| 琥珀强调 | `#FFC857` |
| 珊瑚红 | `#FF6B6B` |
| 青色 | `#54C8FF` |
| 成功绿 | `#3DDC97` |
| 紫 | `#B478FF` |

色块 5 色：

```text
Ruby    #FF6070
Amber   #FFC248
Emerald #54DC8E
Sapphire#54B0FF
Violet  #BA78FF
```

### 2.3 色块（2.5D）

每个色块由三层组成：

1. **底部阴影**：向下偏移 4px，深色，透明度 40%；
2. **主体**：圆角 14px，垂直渐变（顶部亮 8%，底部暗 8%）；
3. **顶部高光**：上半部细长高光，透明度 18%；
4. 边框：1px 同色亮边；
5. 高级色块：中央数字徽章 + 锁链/暗角，数字用白色粗体；
6. 选中：外发光 + 放大 1.06；
7. 拖拽：跟手、轻微倾斜，落点格子高亮。

实现优先用运行时生成的 9-slice/圆角 Sprite，不引入大图集。

## 3. 动效规格

所有动效 60fps，输入在动画期间锁定，动画结束后再接受下一次拖拽。

| 动作 | 时长 | 曲线 | 表现 |
|---|---:|---|---|
| 拖拽跟手 | 实时 | 线性 | 色块跟随指针，偏移不超过 20px |
| 交换 | 120ms | ease-out | 两个色块对调，轻微挤压 |
| 无效交换 | 160ms | ease-in-out | 弹回原位 + 红色轻闪 |
| 消除 | 180ms | ease-out | 白色闪一下 → 缩小到 0.2 → 消失 |
| 方块掉落 | 260ms | ease-in（重力） | 从上方落下，末端 8px 回弹 |
| 补充新块 | 220ms | ease-out | 从顶部进入，按列错开 15ms |
| 连锁 | 80ms | 线性 | 每级连锁延迟，分数浮字 |
| BONUS 触发 | 400ms | ease-out | 全屏压暗、BONUS 横幅、三张卡入场 |
| 倒计时紧张 | 持续 | sin | 最后 5 秒进度条脉冲 + 数字放大 |
| 回合开始 | 300ms | ease-out | 目标分/轮次滑入 |

### 3.1 消除反馈

- 每个被消除的格子生成 4~6 个粒子（同色），粒子池复用；
- 中心飘 `+分数`；
- 连锁时屏幕边缘轻闪，分数倍率显示 `CHAIN x2`；
- 不做全屏大爆炸，保持轻量。

### 3.2 掉落

- 先清空 → 每列独立下落；
- 先落已存在块，再补新块；
- 列之间错开 15ms，避免整板一起动；
- 落点用 8px 回弹，手感更“实”。

## 4. 操作：拖拽交换

替换当前点击两次的逻辑：

1. 指针按下色块 → 选中，放大/发光；
2. 拖动超过 20px → 判断主方向（上/下/左/右）；
3. 目标格相邻且可交换 → 播放交换动画；
4. 目标格被高级色块锁住 → 抖动 + 提示；
5. 松手未超过阈值 → 取消选择；
6. 拖拽过程中显示目标格高亮；
7. 动画期间忽略新的拖拽输入。

兼容鼠标和触摸；不引入第三方手势库。

## 5. 倒计时进度条

顶部 HUD 从“数字”改成“数字 + 横向进度条”：

```text
ROUND 3     TARGET 1,200     SCORE 1,540
[██████████████░░░░░░]  18.4s      COINS 240
```

- 进度条填充比例 = `timeLeft / roundSeconds`；
- 颜色：
  - > 50%：青色；
  - 20%~50%：琥珀；
  - < 20%：珊瑚红 + 脉冲；
- 最后 5 秒数字每秒放大一次；
- 时间归零时进度条闪一下再结束。

## 6. BONUS 触发与表现

### 6.1 触发规则

- 一次玩家交换引发的**本次消除总数 ≥ 5** → 触发；
- 连锁中的总消除数也算本次；
- 触发时：
  - 暂停倒计时；
  - 锁定输入；
  - 播放 BONUS 入场；
  - 三选一。

### 6.2 为什么现在“像没触发”

当前缺少：

- 没有全屏压暗/横幅；
- 没有暂停感；
- 按钮/卡片没有入场；
- 触发条件在连锁结束后才展示，视觉上像“突然弹窗”。

### 6.3 新表现

1. 全屏 40% 暗化；
2. 顶部 `BONUS` 大字从上方落入；
3. 三张卡片从下方错开 80ms 弹入；
4. 背景棋盘轻微降饱和/模糊感（用半透明遮罩，不做真模糊）；
5. 选择后卡片飞向 HUD，0.25s 后恢复。

### 6.4 可验证性

- `bonusTriggeredCount` 写入运行期状态；
- 增加一个测试 case：固定盘面/固定交换，确保一次消除 ≥5；
- replay 截图/日志必须能看到：

```text
BONUS triggered: cleared=6 chain=1 round=3
```

## 7. 专项测试下拉

### 7.1 行为

- 下拉项：`c01 ... c24`；
- 选中后：
  - 写入对应 scenario；
  - 关闭主界面；
  - 直接进入该 case；
- 与 `devsim_replay.py --case` 共用 `CaseRouter`；
- 不在 UI 展示 expected opportunities。

### 7.2 case 呈现

- 编号 + 领域短名，例如：

```text
c18 · 混合
c23 · 动画
c24 · GPU/ANIM/LOAD
```

- 负对照也列出，选中后就是正常基线（用于验证“没有机会时不应硬报”）。

## 8. 基线与劣化

### 8.1 基线（新视觉版）

- 拖拽交换；
- 消除/掉落/BONUS 动效；
- 进度条；
- 共享材质/对象池/脏标记；
- Addressables 异步加载；
- 所有 `legacy_* = false`。

### 8.2 劣化（模拟日常开发）

在基线完成后，逐项恢复“图省事”的写法：

| case 类型 | 劣化方式 |
|---|---|
| UI | HUD 每帧刷新 |
| GPU | 每格一个 Material |
| ANIM | 每帧手写 64 格缩放 |
| LOAD | 商店 `WaitForCompletion` |
| 特效 | 每次消除 Instantiate/Destroy |
| 布局 | 每帧改侧栏尺寸 |
| 资源 | 每格 Texture2D |
| 提示 | 空闲全盘扫描 |

每个劣化必须**只改一处**，并保留原视觉/玩法；否则无法归因。

---

## 9. 验收

1. 主界面只有 2 个按钮 + 1 个下拉；
2. 下拉选中 case 与 replay 命令进入同一局面；
3. 拖拽交换可用，点击不再交换；
4. 消除、掉落、BONUS、倒计时都有可见动效；
5. BONUS 触发有日志/截图证据；
6. 24 case 仍能跑通；
7. 不引入超过 30MB 的资源；
8. 60fps 下无明显卡顿。

## 10. 实施顺序

1. 主界面 + 专项测试下拉；
2. 色块 2.5D Sprite + HUD 进度条；
3. 拖拽输入；
4. 消除/掉落/补充动画；
5. BONUS 可见化 + 触发日志；
6. 重新跑 24 case，确认基线无回归；
7. 逐项恢复 `legacy_*` 劣化，重跑评测。
