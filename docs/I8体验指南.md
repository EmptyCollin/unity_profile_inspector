# I8 考卷台（start_lab）

## 它是什么

**出考卷 + 看得分**。不做诊断、不做采集、不做修复。

```text
组合病例 + oracle + 干净 base  →  test_project/（仓库根目录）
用户用 run.bat 启动产品控制台，自己拿 test_project 去跑工具
考卷台用工具的机会扫描引擎给分（对比 oracle）
```

## 启动

```text
双击 start_lab.bat        # 考卷台，127.0.0.1:8787
或 python scripts\i8_lab.py --port 8787
```

## 1. 生成考卷

页面上勾选病例（任意组合，没有“单 case / 组合”之分），点 **生成考卷**：

- 目标固定为仓库根目录 `test_project/`；
- 如果已有内容，**先整体清理再重建**，保证每次考卷一致；
- oracle 与考卷定义只写在 `runs/i8_lab/paper.json`，**不会进 test_project**；
- 不选任何病例 = 干净卷（负对照），用来验证工具不会乱报。

## 2. 考试（用户自己操作工具）

```text
双击 run.bat
```

`run.bat` 依次检查：仓库布局 → python → unity CLI → Unity Editor 进程；
缺依赖会打印安装指引并停住。检查通过后启动 `start_console.bat`（产品控制台 8765）。
然后在控制台里把 `test_project` 加为工程，正常跑工具。

## 3. 看得分

回到考卷台点 **查看得分**：

- 期望 = oracle 的 `expected_opportunities`（按 `atomic_cases` 反查所选病例）；
- 检出 = 工具机会扫描引擎（`upi.core.opportunity.scan`，与产品控制台“机会建单”同一入口）
  在 `test_project` 上的结果；
- 指标：TP / FP / FN、precision、recall；
- 负对照：期望为空时，`found` 必须为空才算通过；
- `unscored_cases`：没有 oracle pattern 的病例（当前 c03 item label、c04 资产），只出题不计分。

## 已验证

```text
生成 11 病例考卷 → 工具检出 9/9 计分模式，P=1.0 R=1.0，FP/FN 空
空考卷（负对照）→ 检出 0，negative_ok=true
重复生成 → 旧 test_project 被清理，结果一致
test_project 内无 oracle / paper 泄漏
run.bat → 依赖检查通过并拉起 8765 控制台
```

## 边界

- 得分只覆盖**静态机会检出**（代码模式）；运行时 breach、性能 verified 不在考卷内。
- 计分模式是通用代码味道（`new Material`、`ForceUpdateCanvases` 等），
  不是按 case 编号或文件名匹配；clean base 实测 0 检出。
