# I8 Lab 体验指南

## 和产品控制台的分工

| | 产品控制台（`python -m upi ui`，8765，带 token） | I8 Lab（`start_lab.bat`，8787） |
|---|---|---|
| 定位 | 用户正常使用入口 | 开发验收台：用 case 组合出题，验证工具能力 |
| 能做什么 | 工程/探针/事件/聚类/工单/审批/回归/报告 | 组合 case、应用、replay、定向取证、Agent、recipe |
| 分账 | 有（unverified/verified、权限、project_id） | 无，结论不进产品统计 |

产品控制台的“设置 → 探针与采集”与本页共用同一份配置
（`config/i8_lab.json`），包含探针安装/采样开关，以及取证线程、帧数、预算、采样窗口。
改任意一边，下一次取证/采样生效。

## 启动

双击 `start_lab.bat`（纯 ASCII 输出，失败会停住显示原因），或：

```bash
python scripts/ensure_editor.py
python scripts/i8_lab.py --port 8787
```

打开 http://127.0.0.1:8787

- 有窗口但不可达：拒绝再开第二个；
- 没有窗口：只开一次；
- Lab 已开 8787：直接开浏览器，不重复启动。

## 两个模式

Lab 页面顶部切换，两个模式的结论不能混用。

### A. 真实诊断（单 case）

```text
组合到临时工程 → 检查 Unity → 应用到 base → 执行 replay
→ 定向采集 → Agent 诊断 → 查看修复计划 → 执行修复 → 恢复 base
```

采集只跑该 case 声明的窗口，候选只保留目标作用域：

| case | 窗口 | 期望符号 |
|---|---|---|
| c01 | board | `BoardModel.FindMatches` |
| c02 | hud | `ChromaGame.UpdateHud` |
| c03 | hud | `ChromaGame.RefreshItemLabels` |
| c04 | shop | 无符号；断言 `phase=Shop` 且 `shopOpen=true` |

c04 只做资产检测（payload 356352B），没有自动修复 recipe。

### B. 组合自测（覆盖检查）

```text
组合 → 检查 Unity → 应用并编译 → 合并 replay → 覆盖检查
```

只断言：每个 case 的文件是否应用、replay 指令是否合并、编译是否通过。
**不产候选、不做 Agent 归因、不承诺跨 case top8**（这三类请求会被 409 拒绝）。

## 取证参数（可改）

页面上有输入框，或直接改 `config/i8_lab.json`，下一次采集生效：

| 字段 | 默认 | 范围 | 含义 |
|---|---|---|---|
| `evidence_threads` | 8 | 1–64 | HUD 取证扫描线程数 |
| `evidence_frames` | 8 | 1–32 | HUD 取证回看帧数 |
| `evidence_budget_ms` | 6000 | 500–20000 | 主线程扫描硬预算 |
| `board_threads` | 8 | 1–64 | 板子取证线程数 |
| `board_frames` | 4 | 1–8 | 板子取证扫描帧数 |
| `board_budget_ms` | 5000 | 500–20000 | 板子扫描硬预算 |

实测：线程 32→8 后，HUD 采集内存增量 369MB→约 52MB，耗时 8–11s→6–7s，
候选不变（UpdateHud / RefreshItemLabels 仍在）。

## B 模式自动取证（最小闭环）

`python scripts/i8_auto_evidence.py`（先经 Lab 应用 c02+c03 并 replay）：

```text
浅档 profiler 常开 + 每 2s 滚动清帧
→ GC Allocated In Frame 越过阈值（默认 64B，预热 5 帧后才允许触发）
→ 触发帧记下，再录 N 帧（默认 10）
→ dump 触发前 1 帧到触发后 N 帧 → 直接进候选管道
```

已验证（c02+c03）：`breach_frame=3`、`value=131961`、`shape=plateau`、
扫到帧 2..12、24 个函数、候选含 `ChromaGame.UpdateHud` 与
`ChromaGame.RefreshItemLabels`。

形状字段：连续 ≥3 帧仍越界记 `plateau`，否则 `pulse`；级联暂未实现。

## 开销实测（B 模式）

条件：干净编辑器、`sim/project` base + autoplay、浅档、2s 滚动清帧。

| 项 | 关 | 浅档常开 |
|---|---|---|
| 帧时中位 | 16.67 ms | 16.66 ms |
| 进程 CPU/帧 | 40.34 ms | 41.87 ms（+3.8%，3 次配对中位 +1.3%，噪声较大） |
| RSS 峰值 | 2055 MB | 2216 MB（+161 MB，180s 长跑，末端回落） |
| marker 粒度 | — | 8 个（含 ChromaGame.Update / 协程） |

证据：`runs/bench_profiler_*.json`。结论：延迟与内存达标；CPU 在 1~4% 量级，
样本不足以钉死 3% 以内。

## 安全约定

- 不自动开第二个 Unity；停止只按确认 PID；
- `Assets/_Recovery` 保留并忽略，不删备份；
- apply 前要求 `sim/project` 干净；编译失败自动恢复；
- 每次取证结束无条件关闭 profiler 并清帧；编辑器超过 5GB 拒绝采集，
  超过 6GB 或主线程被占导致收尾失败时按 PID 强制停止（break-glass）；
- 采集失败会作废旧候选，不允许 Agent 读上一轮证据。
