# I8 考卷台（start_lab）

## 定位

**出考卷 + 按能力判分**。不做诊断、采集、修复。

```text
组合病例 + oracle + 干净 base  →  test_project/（仓库根目录）
用户用 run.bat 启动产品控制台（或跑 capability_run）去“考试”
考卷台读工具运行产物 findings.json，按“机制 + 位置 + 效果”判分
```

判分**不匹配正则、不匹配 case 编号、不读静态扫描命中**；没有产物就显示“未评估”。

## 启动

```text
双击 start_lab.bat        # 考卷台，127.0.0.1:8787
```

## 1. 生成考卷

勾选病例（任意组合，无单/组合模式），点 **生成考卷**：

- 目标固定 `仓库根/test_project`；已有内容先清理再重建；
- `test_project` 正在 Unity 打开时拒绝清理（避免文件锁）；
- oracle / 考卷定义只写 `runs/i8_lab/paper.json`，不进工程；
- 不选病例 = 干净卷（负对照）。

## 2. 考试

```text
双击 run.bat     # 查依赖 → 启动产品控制台（8765）
```

工具运行会产出 `runs/<run_id>/findings.json`（项目索引在 `runs/projects/<id>/index.json`）。
自动化跑法：

```text
python scripts/capability_run.py --project test_project --project-id test_project \
    --replay runs/i8_lab/paper_replay.json [--repair]
```

它做四件事：跑合并 replay、按动作滚动采集 marker、生成候选、写 findings；
`--repair` 额外找第一个能出源码配方的 finding，执行“应用 → 编译 → 可运行冒烟”。

## 3. 看得分

点 **查看得分**，四个维度：

| 维度 | 判据 |
|---|---|
| 发现 | 工具 finding 的代码锚点（文件 + 方法）命中 oracle 期望；oracle 可用 `accept_methods` 容忍调用方/被调方 |
| 不误报 | 干净卷 findings 必须为空 |
| 修复 | 应用源码配方 → 编译通过 → 能进 Play 正常启动一局；**玩法自测不计入考试** |
| 可复现 | 考卷生成后、同协议指纹的多次运行，findings 位置集合一致 |

修复结论只到 `unverified`（没有同 replay 前后指标复验），`effective` 单列，不冒充 resolved。

## 当前验证（2026-11-13）

```text
11 病例考卷 + capability_run：
  发现 11/11，FP=0，FN=0，precision=1.0，recall=1.0
  修复：应用 1 个源码配方，编译通过，可运行冒烟通过；effective=0（unverified）
  可复现：4 次同协议运行，位置集合一致
干净卷：0 finding，负对照通过
```

## 边界

- 得分只覆盖工具的运行时证据链（marker / 资产度量）；标定阈值、性能 verified 不在考卷内。
- 静态机会扫描（`upi/core/opportunity.py`）保留为产品启发式，**不参与考卷判分**。
- 玩法自测属于体验项，不作为考试门槛；修复只看编译与可运行。
