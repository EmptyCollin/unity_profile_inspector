# UPI 使用说明 — Unity 性能自动监测与优化 Agent

面向"接手就能跑"的读者。所有命令、配置键名、耗时与产物路径都经本机实跑核对过；
凡未实测的能力本文一律不承诺（详见第六节边界）。

---

## 一、它是什么

一个**独立运行的特化 Agent**：盯着 Unity 工程做性能检测，检出问题后归因、开修复方案、
递一张人工审批工单，人批完它自己落地并重新采样验证，全程不需要 AI 助手在场。

三条链路都是普通 Python 进程：
- 操作 Unity：走官方 `unity` CLI 对 Editor 发命令（不写插件、不改工程资产结构）
- 调用模型：`llm_config.yaml` + 环境变量密钥直连 OpenAI 兼容接口
- 人工批准：读写 `decision.json` 文件——批准人可以是任何坐在终端前的人

## 二、前置条件（本机实测版本）

| 依赖 | 要求 | 检查方式 |
|---|---|---|
| Python | 3.14（`C:\Python314\python.exe`） | `python --version` |
| 包 | pydantic 2.12.5、langgraph 1.2.20、openai 2.30.0、PyYAML 6.0.3 | `python -m pip list` |
| Unity CLI | 1.0.0-beta.6，且在 PATH | `unity --version` |
| Unity Editor | 6000.6.7f1，**必须 GUI 模式且进 Play Mode** | `unity status` |
| 模型密钥 | 系统级持久环境变量 `UNITY_PROFILE_INSPECTOR`，由你本人设置 | 见下 |

两条硬约束（不是建议，是实测结论）：

1. **不能用无头模式**。`-batchmode -nographics` 下 `drawCalls/batches/triangles` 恒为 0、
   GPU 显示 `Null Device`（门禁 G16）。渲染类与 GPU 类指标的采样必须在 GUI Editor 播放态。
2. **窗口失焦会停帧**。`runInBackground` 每次域重载被重置回 False，失焦时帧号不推进——
   表现为"采集失败"。采样期（一轮 20~25 分钟）别让 Unity 窗口被长时间抢占。

密钥设置（管线只读环境变量名，永不接触值）：

```powershell
# 用 PowerShell 设置系统级持久变量（需要你本人在终端执行；管线不代设）
setx UNITY_PROFILE_INSPECTOR "你的密钥"
# 设置完要重开终端才生效；之后 python -m upi status 会显示"有"
```

一键自检（会告诉你缺什么）：

```powershell
python -m upi status
```

## 三、六个命令

```
python -m upi status          # 环境自检：CLI/Editor/标定/探针心跳/密钥存在性/巡检配置
python -m upi detect          # 水位检测单轮（读历史标定束，约 1 分钟，不烧积分）
python -m upi patrol-once     # 巡检单轮：发作(只读)+水位(真重采)，约 20~25 分钟
python -m upi monitor         # 前台周期巡检，Ctrl+C 停（外部调度器请用 patrol-once）
python -m upi resume --run <run_id>   # 工单批准后从断点续跑，约 35~45 分钟
python -m upi drill --dry-run         # 演练预检：零成本验 diff 命中与工单渲染
```

**接外部调度器**（Windows 任务计划 / CI）：用 `patrol-once`，别用 `monitor`。
一轮失败返回非零，连续失败达 `max_consecutive_failures` 上限会退出非零——巡检挂了你能知道。

## 四、日常就两条命令

### 4.1 让它自己盯

```powershell
python -m upi patrol-once
```

它做什么：
1. **采前同步**：先把 Editor 内存里的程序集刷成磁盘代码态（防"盘上是缺陷代码、内存里跑着
   已修复代码"这类漏检）；同步不成立就整轮拒采，宁可不测也不出脏数据；
2. **发作通路**：读探针落盘的越界样本（零采样成本）；
3. **水通路**：按标定协议真重采一轮 5 夹具 × 4 窗口；
4. 检出 ⇒ 自动唤起状态机：归因 → 选方案 → 建 git 快照 → **生成工单后停住**，绝不自行改代码。

结果一律落 `runs/patrol_runs.jsonl`（每轮一行，**没检出也写**，这样"在跑"和"睡着"分得清）。

### 4.2 批一张工单

找待批工单（有 `request.md`、无 `decision.json` 的那个目录）：

```powershell
gci runs -Recurse -Filter request.md | ? { -not (Test-Path "$($_.DirectoryName)\decision.json") } | % { $_.DirectoryName }
```

（`upi status` 目前**不**列出待批队列——`ApprovalStore.list_open()` 已实现但没接成命令，
是个已知小缺口。）

工单长这样：`runs/patrol_<时间戳>/approvals/<工单号>/request.md`

工单五件套（缺一构造期拒收，不会递给你半张单）：
1. **证据** — 实测数值 + 噪声带 + 数据档位，全部来自采样，工单自己不产生任何数字
2. **方案** — 具体 diff、每条改动对应到哪条证据（对不上的单不予递交）
3. **预期效应** — 根因与置信度（公式算的，不是模型自评分）、量化改善线及其标定来源
4. **回滚方式** — git 快照 tag + 复位范围
5. **失败预案** — 不批 / 编译失败 / 验证不通过 / 感知门禁 四种情况各怎么办

决定写成同目录 `decision.json`：

```json
{
  "decision": "approve",
  "approver": "你的名字",
  "note": "批的具体内容"
}
```

`decision` 可取 `approve` / `reject` / `defer`。规则（都是实测固化的）：
- 没有这个文件 = 没批；文件坏了 = 没批；**绝不默认放行**；
- `approve` 但缺 `approver` 或缺 `note` = 视同没批（批了没说批什么不算批准）；
- 未批准的轮次**不采基线**，所以被拒不白烧 25 分钟采样成本。

然后续跑：

```powershell
python -m upi resume --run patrol_20261109_105554
```

落地 → 编译门禁 → 改后重采 → 全量守护对比 → 记账。
判定 `resolved` 就保留改动；判出问题则回滚并留完整取证。

## 五、配置：`llm_config.yaml` 的 `pipeline.monitor` 段

```yaml
pipeline:
  monitor:
    enabled: true
    interval_s: 1800               # 巡检间隔（下限 60s，低于此配置校验直接拒）
    windows: 4                     # 与标定链同窗口数（可比性前提）
    fixtures: [CLEAN, F-CPU-01, F-GPU-01, F-ANIM-01, F-LOAD-01]
    episode:
      jsonl: runs/_probe/pb_breach.jsonl
      heartbeat: runs/_probe/pb_hb.txt
      heartbeat_max_age_s: 12
    waterline_timeout_s: 1800      # 5 夹具一轮实测约 15~20 分钟，900 会误杀
    auto_fix:
      enabled: true
      fixtures: [F-CPU-01]         # 只有它有修复方案模板；其余检出后进队列转人工
      live_llm: true               # 真模型归因开关（会烧积分；见下）
    cooldown_s: 1800               # 同夹具两轮唤起的最小间隔，防重复烧成本
    max_consecutive_failures: 3
    budget: {max_review_rounds: 1, max_attempts_per_issue: 1,
             wallclock_s: 3600, max_tokens: 60000}
```

要点：
- **缺这段 = 巡检不启用**，不会用内置默认值悄悄跑起来；
- `live_llm: true` 是本轮实测留下的临时开关。**不打算花积分就改回 false**（改回后归因走
  离线替身，流程照跑、结论不具对外效力）；
- `fixtures` 必须含 `CLEAN`，否则无同期对照，整轮直接拒判（门禁 §8.1）；
- **阈值不在这里**。检测阈值永远来自标定文件，配置里改阈值属被禁操作（G14）。

## 六、能力边界（照抄进任何对外材料，别只说"能检测"）

检出率必须与"测不到的东西"同屏呈现。当前盲区：

1. **记忆体守护实际只剩一项在受保护**：`monoUsedBytes`。
   `monoHeapBytes / totalAllocatedBytes / totalReservedBytes / total_used_per_frame` 经实测
   **不受强制 GC 影响**（Δ=0），量的是编辑器会话累积量而非代码占用，跨会话不可比，
   已一律降级为"未评估"。所以"这次修复有没有多吃内存"只能靠托管堆占用一个口径回答。
2. **GPU 尖峰能检出、不能逐笔归因**：程序侧取不到 Frame Debugger 逐笔明细（全套入口试过），
   归因需人工下钻或真机 B 档。
3. **代码里未被放大的分配风险测不到**：静态扫描器（C+）未建，"规模到 S 才发作"的潜在风险
   当前给不出。
4. **画面/手感回归无自动门禁**：改材质、改动画这类影响感官的改动，验证基建（P2/G3）未落地。
   这类改动按权限矩阵本就永远先报后批。
5. **所有数据是 PC Editor 采样 + 帧预算模拟，不等于中低端真机**。

另外两条诚实说明：
- 泛化结论目前**样本量不足**（同三重签名的独立场景 n=1，升维提案因此 blocked），
  历史统计一律属方法学示范；
- 判定阈值/口径的调整必须附过拟合体检表（六项），当前未接入，所以阈值与权限矩阵不可自动变更。

## 七、跑之前必查的三件事

1. **夹具当前状态决定你能不能复现检出**。第三轮实测保留的修复**已提交**（`df3b074`，
   工作区干净），`F-CPU-01` 现在处于修复态——所以现在跑 `patrol-once`，该夹具会静默，
   这是"修好了"的正确表现，不是坏了。想复现检出演示：把 `CombatSkillManager.cs`
   回退到缺陷态（参照 `upi/agents/_refs/F_CPU_01_defect.cs` 就是那份原文）并提交即可。
2. **不要并发操作版本库**。巡检/续跑期间再开第二个实例，写入前校验会按门禁拒写
   （实测兜住过一次），表现为干净退出而不是数据损坏。
3. **推送 GitHub 若失败**：本机走系统代理，代理端口会变。仓库本地配置已存
   `git config --local http.proxy`，端口变了更新这一项即可（凭据不写入仓库）。

## 八、产物在哪

| 产物 | 路径 |
|---|---|
| 巡检轮次结论（含静默轮） | `runs/patrol_runs.jsonl` |
| 巡检运行时状态（样本偏移/冷却戳） | `runs/patrol_state.json` |
| 每轮原始采集束（约 16MB，可重采） | `runs/patrol_<时间戳>/multiwin_full.json` |
| 工单（给人看的五件套） | `runs/<run>/approvals/<工单号>/request.md` |
| 你的决定 + 消费记账 | 同目录 `decision.json` / `used.json` |
| 运行终态与判定链 | `runs/<run>/state.json`、`runreport.json` |
| 全程 trace（每阶段一条，成本+质量同源） | `runs/<run>/trace.jsonl` |
| 升维提案（只提案，不执行） | `runs/<run>/promotion_proposal.json` |
| 知识库（成功/失败样本同等入库） | `knowledge/patterns.db` |
| 设计、门禁、认知债 | `DESIGN.md`、`AGENTS.md`、`docs/现状与认知债.md` |

自检一遍机制（零成本，不碰 Editor、不烧积分）：

```powershell
python scripts/test_patrol.py       # 巡检 20+ 项
python scripts/test_m4_approval.py  # 人工回路 25 项
python scripts/test_orchestrator.py # 状态机路由 30 项
python scripts/test_m4_wiring.py    # 七节点端到端 22 项
python scripts/test_m3_gates.py     # 快照/权限/编译/回滚门禁 15 项
python scripts/test_memory_guard.py # 记忆体口径 22 项
```
