# UPI 使用说明（v2 / Web 单通道）

> 当前迭代：I4b2b2b2a。旧 ANSI TUI 入口/模块已移除；日常只用 `python -m upi ui`。
> 本文只讲“怎么用”。设计原因见 [DESIGN.md](../DESIGN.md) §14，行为边界见
> [AGENTS.md](../AGENTS.md) §8。

## 0. 先理解两形态

| 形态 | 输入 | 结论 | 用途 |
|---|---|---|---|
| 常驻 | 探针 `breach`/`sample` + 1Hz 哨兵 | 只 `unverified` | 日常发现、best-effort 修复 |
| 回归 | 用户 replay 命令 + 3 次基线 | 可 `verified` | 可复现问题的修复验证 |

常驻“修但不验”= 不做复现验证；编译/启动/异常/回滚等安全验证仍必须。

## 1. 前置与启动

- Python 3.14；
- Unity 6000.6.7f1，图形界面模式（GPU/动画必须在 Play Mode 采）；
- `unity` CLI 在 PATH；
- 模型密钥由你本人设为系统级环境变量 `UNITY_PROFILE_INSPECTOR`；工具只读，
  不收集值。

```powershell
python -m upi status     # 自检
python -m upi start      # 后台启动守护（可跳过，Web 也能巡检）
python -m upi ui         # 本地 Web 控制台，默认 127.0.0.1:8765
```

也可以直接双击 **`run.bat`**：它先检查仓库布局、python、unity CLI、Unity Editor 进程，
缺依赖会打印安装指引并停住；全部通过后启动 `start_console.bat`（产品控制台 8765）。
控制台在**当前终端窗口前台运行**：窗口不关就一直在，关窗口或 Ctrl+C 即停止控制台服务。
守护进程（`python -m upi start`）是独立进程，关控制台不会停它。

`upi ui` 会打印带 token 的本地 URL；浏览器打开即可。服务只绑定本机，
token 走 cookie/查询参数。开发用的 **I8 考卷台** `start_lab.bat`（8787）负责生成
`test_project` 考卷并查看得分，见 `docs/I8体验指南.md`。

## 2. 首次接入：装探针、开采样

1. 首页“探针”卡片点 **安装**：先卸旧 `UpiBreachProbe`，再注入
   `probe/upi_probe_v4.cs`；
2. 进 Unity Play Mode；
3. 点 **采样开**（默认窗口 300 帧）；需要关时点 **采样关**；
4. 首页应看到心跳、事件数（breach/sample）、cluster 数；
5. 不用时点 **卸载**。

装探针失败会如实报错，不会假装成功。旧探针在夹具里是
`[InitializeOnLoad]`，域重载后可能重新挂上；生产随机工程没有旧探针。

## 3. Web 控制台页面

| 页面 | 用途 |
|---|---|
| 首页 | 守护/工程/探针、cluster 数、工单、事件流、探针与巡检按钮 |
| 问题 | cluster 表：指标、波形、相对帧、次数、数据档、值 |
| 工单 | 从 cluster 建单、明细、正式审批、单条批准、执行 |
| 回归 | 新建套件、记录/跑 3 次基线、验证第 4 次、生成报告 |
| 指纹库 | 内置/学习 pattern、命中/未命中/成功失败 |
| 报告 | 回归套件、verified 数、最近 verdict、打开 HTML 报告 |
| 设置 | 当前 profile/工程/探针/指纹库/目录；**探针与采集**（安装/采样开/采样关/卸载 + 取证线程·帧数·预算·采样窗口，保存后与 I8 Lab 共用 `config/i8_lab.json`）；**模式档位**（semi ↔ shadow 人工切换，升 auto 仍走升维提案）；首用勾选 |

> 产品控制台是用户入口；`start_lab.bat`（8787）是开发验收台，用 case 组合出题验证工具能力，
> 两者共用同一份取证配置，但 Lab 的结论不进入产品分账。

## 4. 常驻流程

```text
事件 → 聚类 → 建单 → 批准 → 一次一个 patch → 编译/观测 → keep/rollback
```

1. 首页 **巡检一轮**（或 **自动巡检** 后台每 60s 跑一次）；
2. 工单页 **从当前 cluster 生成工单**；
3. 工单明细看指标/指纹/playbook/权限/计划 diff；
4. 待批工单点 **批准**：填批准人、批语、4 位校验码；
5. blocked/semi 候选还要在明细里 **单条批准**（批量批准不绕过权限闸）；
6. 已批准且 `pending>0` 时点 **执行**：
   - 每个 patch 先 `snapshot`，再 `fixer.execute`（编译门禁/失败回滚）；
   - 成功只记 `applied_unverified`；编译失败 `rolled_back` 并停止后续；
   - 没有可执行 plan 时接口返回 409，不盲改。

**当前现实**：夹具 CPU 能生成真实 plan，但目标是夹具 scripts=`blocked`；
夹具工作区已清理干净，`snapshot()` 可建。真实 Unity 写-编译-回滚 harness
与**缺陷态夹具产品 plan** 均已通过（17/17）。但当前 HEAD 已是修复态，
产品 plan 的 find 段来自缺陷参照，直接套用会 `diff_rejected`；真实用户
工程/产品 plan 仍未闭环。所以默认执行仍会停在 409/权限闸，不是
“已能自动修夹具”。

## 5. 回归流程

1. 回归页 **新建回归套件**：填名称、协议指纹（同 replay/画质/档位）、
   工程路径与场景相对路径；
2. 点 **跑3次基线**：
   - 没填 `command` 且有 project+scene ⇒ 自动 `scene open → Play → 探针采样 →
     Stop`，共 3 次；
   - 填了 `command` ⇒ 执行你的命令（`shlex` 拆分，不经 shell）；
   - 也可以每次跑完 replay 点 **记录本次基线**；
3. 3 次后自动出计划：只收复现率 ≥2/3、非 ambiguous 的 cluster；
4. 修复后跑第 4 次，点 **验证最后一次**：
   - 同协议 + 目标 cluster 消失 + 无新 cluster + 守护不劣化 ⇒ `verified`；
   - 否则 `target_present/new_cluster/guard_regressed/protocol_mismatch`，
     不冒充 verified；
5. 点 **报告** 生成 HTML（runs/_regression/reports/<id>.html）。

**当前现实**：自动 replay 已通；夹具缺陷态 3 次基线 + 修复后 3 次 replay
已 **verified**（GC breach 消失、GC 77.5KB→572B、CPU 守护正常）。
`Memory/TotalUsedBytes` 是窗口值，按 G20 标为未评估盲区，不能对外说“内存
不劣化”。真实用户工程仍未接入。

## 6. 证据与审批规则

- 工单操作共五种：
  - **整单批准**：批准人 + 批语 + 4 位校验码；
  - **整单驳回**：批准人 + 批语（不要校验码）；
  - **退回修改**：批准人 + 意见；工单转 `changes_requested`，意见按机制签名
    带回下一轮建单（`item.change_request`），不改代码；
  - **单条批准**：批准人 + 批语 + 单条 4 位码；批量批准不能替代 blocked/semi；
  - **单条驳回**：批准人 + 批语；只否掉该条，执行器跳过它、其余照常。
- diff 可展开（file/why/find/replace），但只截断展示；
- 审批历史记录动作/人/批语/时间，不记录当时 diff 哈希；
- 常驻成功只 `unverified`，不进成功率分母；回归才可 `verified`。

## 7. 故障与退出

- 探针心跳超 5s：首页会标 stale；先确认 Editor 在 Play、探针未卸载；
- 探针装不上：看首页错误；`unity` CLI 不在 PATH、Editor 不可达都会如实报；
- 工单执行 409：没有可自动执行的 plan，或候选仍需单条批准；
- 工单执行失败：看明细“原因/执行时间线”；编译失败会自动回滚；
- 停止：`python -m upi stop`；UI 关闭不影响后台守护（如已 start）。

## 9. 盲区（必须一起读）

1. GPU 尖峰逐笔归因：仍需 EX-1/B 档或人工；
2. 未放大的代码风险：需 C+ 扫描，当前测不到；
3. 感知类退化：需 M7 T8，当前测不到；
4. 记忆体守护面窄：`monoHeapBytes` 等是会话累积量，跨会话不可比；
   “修复是否多吃内存”当前主要靠 `monoUsedBytes`；
5. batches 注入等价性：Render 类目无汇总 `Batches Count`，SRP 常态两侧同零。

另：数据来自 PC Editor，不等于真机中低端机型；样本不足时趋势只作方法学示范。
