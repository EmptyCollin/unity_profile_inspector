# UPI 使用说明 — Unity 性能自动监测与优化 Agent

面向"接手就能跑"的读者。所有命令、配置键名、耗时与产物路径都经本机实跑核对过；
凡未实测的能力本文一律不承诺（见第六节边界）。

---

## 一、它是什么

一个**独立运行的特化 Agent**：盯着 Unity 工程做性能检测，检出问题后归因、开修复方案、
递一张人工审批工单，人批完它自己落地并重新采样验证，全程不需要 AI 助手在场。

三条链路的形态：
- 操作 Unity：走官方 `unity` CLI 对 Editor 发命令（不写插件、不改工程资产结构）
- 调用模型：`llm_config.yaml` + 环境变量密钥直连 OpenAI 兼容接口
- 人工审批与改配置：**全部在控制台界面里按键完成**（见第三、四节）

## 二、前置条件（本机实测版本）

| 依赖 | 要求 | 检查方式 |
|---|---|---|
| Python | 3.14（`C:\Python314\python.exe`） | `python --version` |
| 包 | pydantic 2.12.5、langgraph 1.2.20、openai 2.30.0、PyYAML 6.0.3 | `python -m pip list` |
| Unity CLI | 1.0.0-beta.6，且在 PATH | `unity --version` |
| Unity Editor | 6000.6.7f1，**必须 GUI 模式且进 Play Mode** | `unity status` |
| 模型密钥 | 系统级持久环境变量 `UNITY_PROFILE_INSPECTOR`，由你本人设置 | `upi status` 只报"有/无" |

两条硬约束（不是建议，是实测结论）：

1. **不能用无头模式**。`-batchmode -nographics` 下 `drawCalls/batches/triangles` 恒为 0、
   GPU 显示 `Null Device`（门禁 G16）。渲染类与 GPU 类指标的采样必须在 GUI Editor 播放态。
2. **窗口失焦会停帧**。`runInBackground` 每次域重载被重置回 False，失焦时帧号不推进。
   界面进 Play 后会**实测帧号是否推进**，不推进就整轮拒采并报 `precondition_failed`——
   不会把"停帧"读成"极稳定健康"（这是历史实测踩过的最危险失效）。

密钥设置（管线只读环境变量名，永不接触值）：

```powershell
# 需要你本人在终端执行；管线不代设、不收集值（I13）
[Environment]::SetEnvironmentVariable("UNITY_PROFILE_INSPECTOR", "<你的密钥>", "User")
```

## 三、入口：一个界面 + 三个生命周期命令

日常操作**只有一个入口**——控制台界面：

```powershell
python -m upi ui        # 进度、开关采样、暂停、立即巡检、取消、改配置、批工单，全在这里按键
```

生命周期命令（只有"第一次把它启动"和"收工"需要终端）：

```powershell
python -m upi status    # 环境自检：CLI/Editor/标定/探针心跳/密钥/巡检配置/守护存活/待批工单数
python -m upi start     # 后台启动常驻守护（不占终端；之后用 ui 附着观察与控制）
python -m upi stop      # 停止守护（走命令通道优雅收尾：先收采样子进程，不是硬杀）
```

"彻底唯一入口"的诚实边界：**任何进程都得有人第一次把它启动，可执行入口消灭不掉。**
真正落地的是"你永远只在界面里操作，不需要知道命令行的存在"。

开发与诊断通道（日常不需要，本文不再当用法宣传）：

```powershell
python -m upi dev <monitor|detect|patrol-once|resume|drill|report|stats>
```

按旧命令名敲会给你迁移提示而不是冷冰冰的"未知命令"。`dev resume` 读到的决定若来自
终端手写，会打印 `approver_source=external` 警告——它绕过了界面的"逐页读完 + 校验码"，
统计里与界面审批可区分。

## 四、日常操作

### 4.1 让它常驻自己盯

```powershell
python -m upi status     # ① 全绿才继续（含待批工单数，守护没起也会扫盘列出）
python -m upi start      # ② 后台起守护，之后按 interval_s 自己排期巡检
python -m upi ui         # ③ 附着控制台看进度与按键操作
```

界面按键（菜单**按当前状态动态给出**；不可用的键照样显示并附原因，不藏起来）：

| 键 | 作用 | 说明 |
|---|---|---|
| `s` | 开 / 关采样 | 关掉后轮次只记 `round_skipped`，绝不占编辑器；配置活过重启 |
| `p` | 暂停 / 继续排期 | 暂停期间不排新轮，但待批工单仍会被接手续跑 |
| `r` | 立即巡检一轮 | 不等排期，手动催一轮 |
| `c` | 取消当前轮 | 走文件通道，粒度是**下一个采样边界**（最长 150s 兜底强杀）；该轮记 `cancelled`，不冒充静默、不占故障配额 |
| `k` | **改运行配置** | 全部可改项都在表单里，见 4.3；不用碰 yaml |
| `a` | 打开待批工单 | 调系统查看器 |
| `d` | **批准 / 驳回工单** | 逐页强制读完五件套 + 手输校验码，见 4.2 |
| `b` | 界面内启动守护 | 必须真的看到心跳才报成功，不把"还在起"报成"启动成功" |
| `x` | 刷新快照 | 只读 |
| `q` | 退出界面 | 只关界面，**不停守护**（两个进程） |
| `Q` | 停止守护并退出 | 不可逆，需手输 token |

确认强度三档：只读=无确认 / 可逆（`s` `p` `r` `c` `k`）=再按一次同键 /
不可逆=手输 token（`Q` 停守护要输 `Q`）。审批（`d`）不走通用 token，改用
更强的两道：逐页读完五件套 + 手输工单页脚校验码——通用 token 每张单都是
同一个字母，留着它只会稀释"读毕码"的注意力。

状态由守护写出的快照派生，界面不自造：`NO_DAEMON / IDLE / ROUND_RUNNING /
AWAITING_DECISION / PAUSED / DEGRADED / UNCALIBRATED`。守护心跳过期一律判"没在跑"，
不会演成"空闲"。

### 4.2 批一张工单（在界面里按 `d`）

工单长这样：`runs/patrol_<时间戳>/approvals/<工单号>/request.md`，五件套缺一构造期拒收：
1. **证据** — 实测数值 + 噪声带 + 数据档位，全部来自采样，工单自己不产生任何数字
2. **方案** — 具体 diff、每条改动对应到哪条证据（对不上的单不予递交）
3. **预期效应** — 根因与置信度（公式算的，不是模型自评分）、量化改善线
4. **回滚方式** — git 快照 tag + 复位范围
5. **失败预案** — 不批 / 编译失败 / 验证不通过 / 感知门禁 四种情况各怎么办

界面流程：逐页读完 5 页（页脚显示"第 i/5 页"）→ 选 `a`批准 / `r`驳回 / `d`暂缓 →
填批准人 → 填批语 → **手输工单末页页脚的 4 位校验码** → 提交。

规则（都是实测固化的）：
- 校验码印在页脚，所以"读到最后一页"是"抄得到码"的必要条件——防没读内容就按回车；
- 码由守护**独立复算**再比对，绕过界面直接塞意向同样批不动（两道闸同源但互不依赖）；
- `approve` 缺批准人或批语 = 视同没批；没有决定文件 = 没批；**绝不默认放行**；
- 批准走的是"意向文件 → 守护落盘"单写者路径：界面只交意向，`decision.json` 必须经
  守护写（含回读确认），两个进程都能写就可能后写覆盖前写；
- 提交后界面等到守护**真的落盘**才报"已生效"，否则只报"意向已提交"——"守护还没跑"
  不会被显示成成功；
- 未批准的轮次不采基线，被拒不白烧约 2.4 分钟/夹具的采样成本。

批准生效后守护自动接手续跑（约 7 分钟一次干净 attempt：改前后各重采 + 编译 + 判定），
落地 → 编译门禁 → 改后重采 → 全量守护对比 → 记账。判定 `resolved` 保留改动，判出问题回滚并留完整取证。

### 4.3 改配置（在界面里按 `k`）

**任何配置项都能在界面改，不需要手改 yaml。** 字段、类型、上下界、嵌套落盘位置
只写在一处（`upi/config/runtime_spec.py`），界面表单、守护受理、状态导出三处从它派生——
以前分三处手写，漏改任意一处的后果是"界面显示改成功了、守护按未知字段静默丢弃"。

| 项 | 含义 | 边界 |
|---|---|---|
| `interval_s` | 巡检间隔 | 60~86400 秒 |
| `windows` | 每夹具采样窗口数 | 2~12（**改动有代价，见下**） |
| `cooldown_s` | 同夹具两轮唤起的最小间隔 | 0~86400 秒 |
| `waterline_timeout_s` | 重采超时 | 60~7200 秒 |
| `episode_heartbeat_max_age_s` | 探针心跳可接受年龄 | 2~300 秒 |
| `max_consecutive_failures` | 连续失败熔断阈值 | 1~20 次 |
| `budget_max_review_rounds` | 单问题审查轮上限 | 0~10 轮 |
| `budget_max_attempts_per_issue` | 单问题修复尝试上限 | 1~10 次 |
| `budget_wallclock_s` | 单轮墙钟上限 | 60~72000 秒 |
| `budget_max_tokens` | 单轮 token 上限 | 0~2000000 |
| `auto_fix_enabled` | 自动修复总开关 | y/n |
| `live_llm` | 真模型归因（**花积分**） | y/n |

- 采样总开关不在表单里，走 `s` 键（有独立的 `sampling_enabled/disabled` 留痕事件）；
- **`windows` 有代价提示**：该值进协议指纹，改完与既有标定基线不可比（G7 会硬拒判定，
  不是静默比错），必须重新标定才恢复检出能力。界面会先报代价、要求显式确认，
  改完结果行再提醒一次。填了没变的值不会谎报代价；
- 上下界是**设计护栏**（不是采样实测值）：拦住 `interval=1` 这种当场烧穿积分的输入；
- 改动只把**改动项**写进覆盖层 `runs/daemon_conf.json`，不会把从没改过的键固化进去
  （整份写盘会让 `llm_config.yaml` 的打底永久失效）；落盘失败会明说"本次改动只存在于内存"；
- **缺配置段 = 巡检不启用**，配置读不出来时**默认关采样**并留痕（fail-closed）——
  坏配置时人需要的是"停下来告诉我"，不是"替我决定继续跑"；
- `live_llm: true` 会持续烧积分（守护每轮都调真模型），不打算花就按 `k` 改回 n；
- **阈值不在配置里**。检测阈值永远来自标定文件，配置里改阈值属被禁操作（G14）；
- `fixtures` 清单与探针路径属工程上下文（阶段 7 ProjectProfile 的范畴），不作运行期手改项。

## 五、能力边界（照抄进任何对外材料，别只说"能检测"）

检出率必须与"测不到的东西"同屏呈现。当前盲区：

1. **记忆体守护实际只剩一项在受保护**：`monoUsedBytes`。
   `monoHeapBytes / totalAllocatedBytes / totalReservedBytes / total_used_per_frame` 经实测
   **不受强制 GC 影响**（Δ=0），量的是编辑器会话累积量而非代码净占用，跨会话不可比，
   已一律降级为"未评估"。所以"这次修复有没有多吃内存"只能靠托管堆占用一个口径回答。
2. **GPU 尖峰能检出、不能逐笔归因**：程序侧取不到 Frame Debugger 逐笔明细（全套入口试过），
   归因需人工下钻或真机 B 档。
3. **代码里未被放大的分配风险测不到**：静态扫描器（C+）未建，"规模到 S 才发作"的潜在风险
   当前给不出。
4. **画面/手感回归无自动门禁**：改材质、改动画这类影响感官的改动，验证基建（P2/G3）未落地。
   这类改动按权限矩阵本就永远先报后批。
5. **所有数据是 PC Editor 采样 + 帧预算模拟，不等于中低端真机**。
6. **只服务内置夹具工程**。与任意 Unity 工程协作所需的 ProjectProfile 化、冷启动标定向导
   在阶段 7/8，尚未落地——现在把工程路径写死在夹具上，别的项目接不进来。

另外两条诚实说明：
- 泛化结论目前**样本量不足**（同三重签名的独立场景 n=1，升维提案因此 blocked），
  历史统计一律属方法学示范；
- 判定阈值/口径的调整必须附过拟合体检表（六项），当前三项 incomplete，所以阈值与权限
  矩阵不可自动变更。

## 六、跑之前必查的三件事

1. **夹具当前状态决定你能不能复现检出**。第三轮实测保留的修复已提交（`df3b074`，
   工作区干净），`F-CPU-01` 现在处于修复态——所以现在巡检该夹具会静默，
   这是"修好了"的正确表现，不是坏了。想复现检出演示：把 `CombatSkillManager.cs`
   回退到缺陷态（参照 `upi/agents/_refs/F_CPU_01_defect.cs`）并提交即可。
2. **不要并发操作版本库**。巡检/续跑期间再开第二个实例，写入前校验会按门禁拒写
   （实测兜住过一次），表现为干净退出而不是数据损坏。
3. **推送 GitHub 若失败**：本机走系统代理，代理端口会变。仓库本地配置已存
   `git config --local http.proxy`，端口变了更新这一项即可（凭据不写入仓库）。

## 七、产物在哪

| 产物 | 路径 |
|---|---|
| 巡检轮次结论（含静默轮） | `runs/patrol_runs.jsonl` |
| 守护事件流（轮次/进度/检出/工单/命令/自愈动作） | `runs/daemon_events.jsonl` |

| 命令动作 trace（与判定轮次分轴统计，不混算） | `runs/daemon_cmdtrace/trace.jsonl` |
| 每轮原始采集束（约 16MB，可重采） | `runs/patrol_<时间戳>/multiwin_full.json` |
| 工单五件套 | `runs/<run>/approvals/<工单号>/request.md` |
| 决定 + 消费记账 | 同目录 `decision.json`（含 `decided_via` 来源标记）/ `used.json` |
| 运行终态与判定链 | `runs/<run>/state.json`、`runreport.json` |
| 全程 trace（每阶段一条，成本+质量同源） | `runs/<run>/trace.jsonl` |
| 知识库（成功/失败样本同等入库） | `knowledge/patterns.db` |
| 历史统计报告（HTML，`upi dev report` 生成） | `dashboard/报告.html` |
| 设计、门禁、认知债 | `DESIGN.md`、`AGENTS.md`、`docs/现状与认知债.md` |

## 八、一分钟上手序列

```powershell
python -m upi status      # ① 全绿才继续（含守护存活、待批工单数）
python -m upi start       # ② 后台起守护
python -m upi ui          # ③ 唯一操作入口：看进度、按 s/r/c/k/d 干活
# ④ 有待批工单 → 按 d → 逐页读完 5 页 → a 批准 → 填批准人与批语 → 输页脚 4 位码
#    守护随即自动续跑修复+验证，进度在同一界面看
python -m upi stop        # ⑤ 收工（优雅停止，会先收采样子进程）
```

界面起来发现守护没跑，会直接给 `b` 启动守护；不想常驻只想验证单轮：
`python -m upi dev patrol-once`（前台阻塞约 12 分钟）。
