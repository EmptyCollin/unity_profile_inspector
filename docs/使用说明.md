# UPI 使用说明 — 帮你盯着 Unity 项目的性能机器人

这是一份"照着做就能跑起来"的说明。文中每条命令、每个数字、每个产物路径都在
本机真实跑过；没跑出来的能力，本文一个字不承诺（边界全在第五节）。

---

## 一、一句话说清它是干什么的

你有一个 Unity 项目，性能上可能有问题（卡、掉帧、 Draw Call 太多、内存涨）。
这套东西就是一个**自动巡检机器人**：

1. 它常驻后台，隔一段时间自动打开你的项目跑一轮"体检"（采样测性能数据）；
2. 发现指标不对劲，它会分析"病根在哪"，并起草一份**修复方案**；
3. 它**不会自己动手改代码**——先把方案写成一张"工单"递给你，等你批准；
4. 你批了，它才改，改完再测一轮，用数据证明"确实变好了、且没把别的搞坏"；
   没变好或者搞坏了别的，它自动回滚，一切恢复原样；
5. 每次体检、每张工单、每个决定都留了痕，随时可以翻旧账。

打个比方：它像一个住在你项目里的**体检医生**——检查、出报告、开处方都要做，
但"做手术"（改代码）必须等你签字。

它怎么操作 Unity？走官方的 `unity` 命令行工具直接指挥打开着的编辑器，
不装插件、不动你的工程文件结构。它用什么"大脑"分析？一个大模型
（配置在 `llm_config.yaml`，密钥放在你的系统环境变量里，程序只见变量名、
永远碰不到密钥本身）。

## 二、跑之前，电脑上得有这些东西

| 东西 | 要求 | 怎么检查 |
|---|---|---|
| Python | 3.14（本机在 `C:\Python314\python.exe`） | `python --version` |
| 几个 Python 包 | pydantic / langgraph / openai / PyYAML，版本见下表* | `python -m pip list` |
| Unity 命令行工具 | 1.0.0-beta.6，装在 PATH 里 | `unity --version` |
| Unity 编辑器 | 6000.6.7f1，**图形界面方式打开，且要能进播放模式** | `unity status` |
| 模型密钥 | 你自己设的系统环境变量 `UNITY_PROFILE_INSPECTOR` | `python -m upi status` 会报"有/无" |

\* 实测通过的版本：pydantic 2.12.5、langgraph 1.2.20、openai 2.30.0、PyYAML 6.0.3。

**两条铁律，不是建议，是踩过坑之后写死的**：

1. **不能用无头模式**（不带图形界面那种）。实测发现：无头模式下 Draw Call、
   合批、三角面数这些渲染指标永远是 0，显卡显示成"空设备"——采了等于白采。
2. **窗口不能失去焦点**。Unity 编辑器在后台没焦点时会停止出新帧。界面进播放
   模式后会先验证"帧号真的在往前走"，不往前走就整轮拒收数据并明说原因。
   （历史教训：曾经把"停帧"读成"画面稳如泰山"，这是最危险的一种假健康。）

设置密钥（需要你本人在 PowerShell 里跑一次，程序自己绝不代设、也不收集值）：

```powershell
[Environment]::SetEnvironmentVariable("UNITY_PROFILE_INSPECTOR", "<你的密钥>", "User")
```

设完要开一个新终端才生效。

## 三、总共就四个命令，日常只用一个界面

**第一次启动它（要终端）：**

```powershell
python -m upi status    # 体检前的体检：CLI/编辑器/标定/密钥/守护进程全查一遍，全绿再往下
python -m upi start     # 后台启动巡检机器人（不占终端）
python -m upi ui        # 打开控制台界面 ← 之后所有操作都在这里按键，不用再碰命令行
python -m upi stop      # 收工：优雅地停掉机器人（会先收拾采样进程，不是硬杀）
```

说句实在话："唯一入口"这种话不敢说满——任何程序总得有人第一次把它启动。
但启动之后，你确实可以永远只在界面里按键，不需要知道任何命令的存在。

（还有一个 `python -m upi dev ...` 的开发调试通道，日常用不到，此处不展开；
按旧命令名敲会提示你新名字，不会甩一句"未知命令"。）

## 四、日常怎么用它

### 4.1 控制台界面上的按键

菜单会按当前状态动态变化。干不了的事**照样显示但变灰，并写明为什么干不了**
（比如"轮次进行中不能并发标定"），不搞神秘消失。

| 键 | 干什么 | 一句话说明 |
|---|---|---|
| `r` | 立即巡检一轮 | 不等排期，手动催一轮体检 |
| `s` | 选采样档位 | 三档：**关**（不测）/ **稳态**（加载完再开测，及格线用正常值）/ **全程**（开着进加载也测，加载期的卡顿线放宽一档，越了放宽线才响）。关掉后到点只记一笔"跳过"，绝不占着编辑器；设置重启不丢 |
| `p` | 暂停/继续排期 | 暂停只是不再自动开新轮；等你批的工单不会被耽误 |
| `c` | 取消当前轮 | 温和取消，在下一个采样间隙停下来；这一轮记为"已取消"，不算故障 |
| `d` | 批准/驳回工单 | 核心操作，见 4.2 |
| `a` | 打开待批工单 | 调系统查看器看原文 |
| `k` | 改运行配置 | 巡检间隔、预算上限等全在表单里改，见 4.3，不用碰任何配置文件 |
| `n` | 注册新工程 | 想让它盯一个新 Unity 项目？问几个问题就建好档案。⚠️ 改的是"下次启动"的默认工程，正在跑的机器人要按 `Q` 停掉再按 `b` 启动才会换过去 |
| `l` | 跑标定向导 | 新工程接入第二步：先采一轮"正常波动范围"当参照（要占用编辑器十几分钟，期间不会插巡检轮）。没有基准场景的工程会当场拒绝并告诉你出路，不白烧十几分钟 |
| `f` | 改下限目标表 | 给它定"及格线"：帧率不得低于多少、Draw Call 不得超过多少。线提上去，下一个瓶颈就暴露出来。新建表的第一条必须写明线的出处 |
| `b` | 界面里直接启动机器人 | 必须真的看到心跳才报"启动成功"，不把"还在起"糊弄成"起好了" |
| `x` | 刷新快照 | 只读，随便按 |
| `q` | 退出界面 | 只关窗口，**机器人继续在后台干活** |
| `Q` | 停机并退出 | 不可逆，要手输一个字母确认 |

**确认强度分三级**，按动作的危险程度来：
- 只读（`x`）：按了就执行；
- 可逆（`s` `p` `r` `c` `k` `n` `f` `l`）：再按一次同键确认；
- 不可逆（`Q` 停机）：要手输大写字母 token（`Q` 输 `Q`）。
  `n` 注册要输 `N`、`f` 改下限表要输 `F`——下限表写坏了，所有"及格线"判据
  就全没了，所以也按重操作对待。

界面显示的状态（空闲/跑轮中/等你批单/已暂停等）全部来自后台机器人写出的
实时快照，界面自己不编状态。心跳一过期就老实报"没在跑"，不会演成"空闲"。

### 4.2 批一张工单（按 `d`）——最重要的环节

机器人在你签字前什么都不会改。工单在
`runs/patrol_<时间戳>/approvals/<工单号>/request.md`，内容固定五件套，缺一条
工单根本生成不出来：

1. **证据** — 实测数字＋正常波动范围＋数据来源档位。工单自己不产数字，
   每个数都能倒查到采样文件；
2. **方案** — 具体改哪几行代码，每条改动对应哪条证据。对不上号的改动
   不允许出现在方案里；
3. **预期效果** — 病根判断和把握度（把握度是公式算的，不是模型自己打分），
   以及"改善到什么程度才算修好"的量化线；
4. **怎么回滚** — git 快照点位＋恢复范围；
5. **失败预案** — 不批怎么办、编译失败怎么办、验证不过怎么办，各写清楚。

**批准流程故意做得"麻烦"**（防的就是看都没看就按回车）：
逐页读完 5 页（每页页脚标"第 i/5 页"）→ 选 `a` 批准 / `r` 驳回 / `d` 暂缓 →
填批准人姓名 → 填批语 → **手抄末页页脚的 4 位校验码** → 提交。
校验码印在最后一页，所以"抄得到码"等于"真的读完了"。这个码由后台机器人
独立复算比对，绕过界面直接改文件塞"批准"是批不动的。

几条实测固化的规矩：
- 没填批准人或批语 = 没批；没有决定文件 = 没批，**绝不默认放行**；
- 你的批准先写成"意向"，由后台机器人复述落盘（两个进程都能写同一份文件
  迟早互相覆盖，所以只许机器人一个作者）；
- 界面要等到机器人**真的落盘**才报"已生效"，否则只说"意向已提交"——
  "机器人还没接住"永远不会被显示成成功；
- 没批的轮次不会预先采样，驳回不白烧钱（每个夹具约 2.4 分钟的采样成本）。

批准之后，机器人自动接着干完剩下的活（约 7 分钟：改前复测 → 改代码 →
编译检查 → 改后复测 → 全指标对比 → 记账）。数据证明变好了就保留；
没到判定线或弄坏了别的指标，自动回滚并留完整记录。

### 4.3 改配置（按 `k`）

**任何配置都在界面表单里改，不需要手改任何 yaml 文件。**
每个字段的名称、类型、上下限只定义在一处，界面表单、机器人受理、状态导出
三处都从它自动生成——以前分三处手写，漏改任何一处的后果是"界面显示改好了、
机器人其实悄悄丢弃了"。

| 项 | 白话含义 | 允许范围 |
|---|---|---|
| `interval_s` | 每隔多久自动巡检一轮 | 1 分钟 ~ 24 小时 |
| `windows` | 每轮采几个窗口 | 2~12（⚠️ 有代价，见下） |
| `cooldown_s` | 同一个对象两轮之间的最短间隔 | 0 ~ 24 小时 |
| `waterline_timeout_s` | 一轮采样最多容忍多久 | 1 分钟 ~ 2 小时 |
| `episode_heartbeat_max_age_s` | 探针心跳最多允许多旧 | 2~300 秒 |
| `max_consecutive_failures` | 连错几轮后熔断停机 | 1~20 |
| `budget_max_review_rounds` | 一个问题最多复审几轮 | 0~10 |
| `budget_max_attempts_per_issue` | 一个问题最多试修几次 | 1~10 |
| `budget_wallclock_s` | 单轮最多跑多久 | 1 分钟 ~ 20 小时 |
| `budget_max_tokens` | 单轮模型用量上限 | 0~200 万 |
| `auto_fix_enabled` | 自动修复总开关 | 开/关 |
| `live_llm` | 调用真实模型做归因（**花积分**） | 开/关 |

要留意的几点：
- **改 `windows` 的代价**：这个数变了，新旧数据就不可比（协议指纹对不上，
  系统会硬拒对比而不是悄悄比错），必须重新标定才有检出能力。界面会先讲
  代价、要你显式确认，改完再提醒一次；
- 上下限是**护栏**：拦住 `interval=1 秒` 这种能把积分当场烧穿的输入；
- 你在界面改的东西只写进一个覆盖文件（`runs/daemon_conf.json`），重启不丢，
  但不会把没改过的项也固化进去；写盘失败会明说"这次改动只在内存里"；
- **读不出配置 = 自动关采样**（宁可停也不替你决定继续跑）；
- `live_llm` 开着 = 每轮都在花积分，不想花就按 `k` 改回关；
- **检测阈值不在这个表单里**：阈值永远来自标定文件，想在这改阈值属禁用项。

## 五、它现在还做不到什么（对外介绍必须连着这段一起说）

只说"能检测"不说"测不到什么"，等于误导。当前盲区：

1. **内存问题只剩一把尺子**：只有托管堆占用（`monoUsedBytes`）能可靠回答
   "这次修复有没有多吃内存"。另外几个常见内存指标实测不受强制回收影响，
   量的是编辑器会话累积量，跨会话没法比，已诚实降级为"未评估"。
2. **显卡尖峰：能发现、说不出是哪一笔**：某个尖峰存在，它能报；具体是哪个
   绘制调用造成的，程序侧拿不到逐笔明细，要人工用帧调试器下钻或上真机。
3. **"以后量大了会炸"这类潜在风险测不到**：静态扫描器还没建。
4. **画面和手感的回归没有自动门禁**：改材质、改动画这类影响观感的改动，
   自动验证基建未落地——所以这类改动本来就永远走"先报后批"，不许自动执行。
5. **所有数据来自 PC 编辑器采样**，不等于中低端手机真机的表现。
6. **任何 Unity 工程都能接入体检，但"自动开药方"只覆盖已建好模板的问题类型**。
   没见过的机制，检出后一律转人工——把模板"聪明地"硬套到陌生代码上会改错
   东西，宁可不接。已实测走通：用官方模板新建的轻量 URP 工程，
   注册 → 采样 → 标定 → 检出 → 巡检全链无需改一行代码。
7. **两套判据能力不同**："及格线"检查（按 `f` 配表）任何工程随时可用；
   "相对基线"检查依赖同轮在场的基准场景，缺了它就只出及格线结果，
   并且会标注"误报率无法测量"——不会把"没测"报成"零误报"。

另外两句实话：
- 现在样本量还不够下"泛化结论"（同一类问题的独立场景只有 1 个），
  历史统计目前属于**方法学示范**；
- 阈值和权限的任何自动调整都被过拟合体检表卡着（六项里三项还没测齐），
  所以这些变更只能人工做。

## 六、跑之前必查的三件事

1. **演示用的问题可能已经被修掉了**。内置夹具工程上一轮真实修复成功、改动
   已提交（新历史里是 `c7ca3ad`），所以 `F-CPU-01` 这个缺陷现在是**治好**的
   状态——现在巡检它会安静无异常，这是"修好了"的正确表现，不是坏了。
   想重看一遍"检出→工单→修复"的完整演示：把
   `fixtures/upi-fixture/Assets/UpiFixtures/F_CPU_01/CombatSkillManager.cs`
   回退成缺陷版（缺陷版原文备份在 `upi/agents/_refs/F_CPU_01_defect.cs`），
   提交后即可复现。⚠️ 这属于人工操作——夹具脚本按规则（AGENTS §3）对修复
   Agent 永久禁用自动改动。
2. **别同时开两份**。一轮巡检/续跑没结束就开第二个实例，写入前的校验会按
   门禁拒写（实测兜住过一次），表现是干净退出而不是数据损坏。
3. **推送 GitHub 失败先查代理**。本机走系统代理且端口会变，仓库配置里存了
   `git config --local http.proxy`，端口变了只更新这一项即可（凭据不入库）。
   另外凭据走图形弹窗，**在无法弹窗的后台环境里推送会一直挂住**——推送
   请在你自己的终端里做。

## 七、跑出来的东西都在哪

所有留痕都在 `runs/` 目录。常用这几样：

| 想看什么 | 去哪看 |
|---|---|
| 每轮巡检结论（含"没查出问题"的轮） | `runs/patrol_runs.jsonl` |
| 机器人全程事件流水 | `runs/daemon_events.jsonl` |
| 此刻状态快照（界面就是读它） | `runs/daemon_status.json` |
| 你在界面改过的配置 | `runs/daemon_conf.json` |
| 待批/已批的工单原文 | `runs/<轮次>/approvals/<工单号>/request.md` |
| 你的决定和消费记录 | 同目录 `decision.json`、`used.json` |
| 某一轮的完整判定链 | `runs/<轮次>/state.json`、`runreport.json`、`trace.jsonl` |
| 原始采样数据（约 16MB/轮，可重采） | `runs/<轮次>/multiwin_full.json` |
| 知识库（成功失败样本都入库） | `knowledge/patterns.db` |
| 历史统计网页报告 | `dashboard/报告.html` |
| 设计文档 / 规则契约 / 认知债清单 | `DESIGN.md`、`AGENTS.md`、`docs/现状与认知债.md` |

**关于 `runs/` 和 Git 的关系（2026-11-10 定下的双仓库结构）**：
- `runs/` 整体**不进 GitHub**——里面有本机绝对路径和大量可重采的原始数据；
- 但本地仍要能翻旧账，所以 `runs/` 里自己挂了一个**独立 git 仓库**：
  在 runs 目录下照常 `git log`、`git diff`，工单、决定、报告的逐版本历史
  都在。这个仓库没有远端、永远不推送，换电脑时整个 `runs/` 目录拷走即可。
- 编辑器的回滚能力不受影响：回滚走主仓库的快照标签，`runs/` 从来不是
  回滚对象。

想验证机制是否健全（纯本地，零成本，不碰编辑器、不烧积分）：

```powershell
python scripts/test_daemon.py         # 常驻机器人与命令通道 76 项
python scripts/test_ui_actions.py     # 界面状态机/按键白名单/配置表单/审批闭环 132 项
python scripts/test_recovery.py       # 自愈边界与配置契约 55 项
python scripts/test_patrol.py         # 巡检 55 项
python scripts/test_m4_approval.py    # 人工回路 26 项
python scripts/test_orchestrator.py   # 流程状态机路由 41 项
python scripts/test_m4_wiring.py      # 七节点端到端 22 项
python scripts/test_memory_guard.py   # 内存指标口径 22 项
python scripts/test_aggregate.py      # 统计聚合 62 项
python scripts/test_report.py         # 报告层 31 项
python scripts/test_m3_gates.py       # 快照/权限/编译/回滚门禁 15 项
python scripts/test_fixture_split.py  # 夹具隔离闸 21 项
python scripts/test_onboarding.py     # 注册向导 34 项
python scripts/check_fixture_split.py # 隔离闸本体的三条机器检查
```

## 八、一分钟上手

```powershell
python -m upi status      # ① 全绿再继续
python -m upi start       # ② 后台启动机器人
python -m upi ui          # ③ 打开界面——之后全靠按键
# ④ 出现待批工单 → 按 d → 读完 5 页 → a 批准 → 填名字和批语 → 抄页脚 4 位码
#    机器人自动完成"修改+复测验证"，进度在同一个界面里看
python -m upi stop        # ⑤ 收工
```

界面打开发现机器人没在跑：按 `b` 直接在界面里启动。
不想常驻、只想试一轮：`python -m upi dev patrol-once`（前台阻塞约 12 分钟）。

接入你自己的工程（而不是内置演示工程）：界面按 `n` 注册 → 按 `l` 标定
（十几分钟）→ 按 `f` 定及格线 → 之后它就开始盯你的工程了。
